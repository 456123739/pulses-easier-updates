## 一、改了什么

### 1. 开发者端 STEP 1：只剩一个「整合包定位」
- 去掉「启动器整合包 / 本地整合包目录」两档切换。选实例目录、实例里的任意文件、或 Modrinth 格式的
  `.zip` / `.mrpack` 都认，类型由后端判断（`app/core/pack_source.py`）。
- 判断很便宜：目录只 `scandir`（向上 8 层），zip 只读中央目录，**绝不解压、绝不哈希**；
  认出类型立刻返回（`phase=loading`），扫描/解析在后台线程；连续拖两个包时后来居上。
- 误拖 `.eapack` → 明确拒绝并说明原因；没有 `modrinth.index.json` 的 zip → 直说只认 Modrinth 格式。
- 拖入（DOM drop）按角色路由，开发者端不再走玩家端定位逻辑。

### 2. 导出内容：并进「更新范围」+ 新增「特殊导出选项」
- 删掉左栏「导出内容」勾选面板（顶层策略与排除本来就由「更新范围」表表达）。
- 右栏新增「特殊导出选项」（`app/core/export_specials.py`）：OptiFine 画质设置、已禁用的 Mod、
  JEI、帕秋莉、EMI、已绘制的地图、截图、录像、本机操作记录。**扫到才出现，默认一个都不带**；
  勾上才进包（重扫后文件出现在「更新范围」），取消立刻退出。
- 规则复用 `export_rules` 同名 key，展开顺序/优先级/固定排除段不变。
  与 PCL 的唯一差异：`optifine` 在 PCL 里默认勾，这里剔掉（画质设置跟显卡走），有测试钉住。

### 3. 更新日志：长按钮 + 独立窗口（所见即所得）
- Tiptap 3 + tiptap-markdown；三视图同一份内容：**编辑**（富文本）/ **预览**（玩家端抽屉同一套排版）/
  **Markdown**（真正写进 `.eapack` 的原文，可直接改并回填）。
- 400ms 防抖回写，关窗不丢；编辑器单独切 chunk（548 kB / gzip 188 kB），主包仍 433 kB / gzip 140 kB。

### 4. CurseForge API Key
- 默认用 PCL 内置那把（`app/core/cf_key.py`），没填过也能查 CF；填了自己的用自己的；
  首选项里多一个「用回内置」，状态显示三态（内置 / 自定义 / 已禁用）。
- 优先级：`PULSES_CF_KEY` 环境变量 → 用户保存 → 内置；给空串 = 不查 CF。

### 5. 顺手修的真 bug
- 从实例导出的 `.eapack`，`ea_manifest.json` 少了 `excluded_folders`（zip 路径有），已补齐对齐。
- CurseForge 的 401 以前只当普通网络错误，现在归入「授权失败」，提示更准确。
