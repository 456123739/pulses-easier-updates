# 大文件资源归档（`resources` 分支）

`main` 只放源码。**体积大、平时用不到、但需要长期追溯**的产物统一放在同一个仓库的
`resources` 分支里，用 tag 做批次版本管理。

* 分支：[`resources`](https://github.com/456123739/pulses-easier-updates/tree/resources)（孤立分支，没有共同历史，不影响 `main` 的提交线）
* 最近一批：tag **`resources-2026-11`**
* 清单：[`INDEX.md`](https://github.com/456123739/pulses-easier-updates/blob/resources/INDEX.md)
  与机器可读的 [`manifest.json`](https://github.com/456123739/pulses-easier-updates/blob/resources/manifest.json)（含每个文件的 sha256）

## 里面有什么

| 路径 | 内容 | 说明 |
|---|---|---|
| `releases/*.zip` | 历次「完整项目包」 | `git archive` 生成，解压即完整工程；从 v0.5.0 到当前版本 |
| `logs/*.log` | 历次单元 / 端到端测试运行日志 | `main` 里已忽略 `tests/logs/`；结论汇总在 `CHANGELOG.md` 与 `docs/测试记录-*.md` |

## 怎么取用

```bash
# 1) 只取一个文件，不动工作区（推荐）
git fetch origin resources
git show resources:releases/pulses-easier-v0.11.2-full.zip > pulses-easier-v0.11.2-full.zip

# 2) 取某一批（tag）里的文件
git show resources-2026-11:releases/pulses-easier-v0.11.2-full.zip > out.zip

# 3) 想把整个归档摊到一个目录里看
git worktree add ../pulses-resources resources
# 看完删掉：
git worktree remove ../pulses-resources

# 4) 校验
sha256sum out.zip   # 与 INDEX.md / manifest.json 里的值比对
```

> 注意：这些文件**不再**出现在 `main` 的工作树里，`release/` 已在 `.gitignore` 中。
> 直接在 `main` 上 `ls release/` 是空的，这是预期行为。

## 新增一批归档（维护者）

当又要腾出空间、或想给某个版本留档时：

```bash
# 1) 准备一个干净目录，只放要归档的文件
git worktree add -B resources ../pulses-resources resources
cd ../pulses-resources
cp /path/to/pulses-easier-v0.12.0-full.zip releases/
# 2) 更新 INDEX.md / manifest.json（重算 sha256）
# 3) 提交并打本批次的 tag
git add -A && git commit -m "resources: 归档 v0.12.0 完整包（2026-12）"
git tag -a resources-2026-12 -m "资源归档 2026-12"
git push origin resources --tags
```

约定：

* **一批一个 tag**（`resources-YYYY-MM`），tag 指向当批完成时的分支提交，方便回溯"当时有哪些文件"。
* 每次归档都更新 `manifest.json` 的 `version` / `created` / `source_commit`，并重算 `total_bytes`。
* 文件名保持不变（带版本号），**不要覆盖**已归档的文件——历史留档的意义就是可复现。

## 为什么不用 Git LFS / GitHub Release

* **Release**：只覆盖发行版产物，拿不到"任意历史版本的完整包 + 当时的测试日志"；
  而且 Release 资产和 git 历史是两套东西，追溯时要两边找。现在新版本的 Windows 包仍发在 Release，
  源码包在 `resources`，两处都能拿。
* **LFS**：会给所有克隆者增加 LFS 依赖和配额成本；这些文件只是"留档"，不在构建链路上。
* **孤立分支**：和 `main` 无共同历史，`git clone` 默认不下载（省流量），需要时 `git fetch` 一次即可。

## 什么时候该归档

* `release/*.zip` 这类完整包（单个 1~8 MB，一次发布一份）
* 大体积测试产物、截图批次、压测数据
* 判定标准：**不进构建、不进运行、平时不读，但出问题时要能翻出来对证**

不该放进来的：源码、配置、文档、小图标（`assets/` 里那些几十 KB 的仍留在 `main`）。
