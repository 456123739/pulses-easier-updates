# Easier v0.6.0 — Windows 手动验证清单

> 开发环境没有显示器，GUI 交互（窗口渲染、拖拽手感、滚轮翻页）只能做
> 桩级测试。下面这 10 条请在 Windows 10 上过一遍，重点是这一版新做的
> **应用（替换/更新）阶段**。每条都写清了"该看到什么"，不对就是有问题。

## 准备

1. 找一个真实的整合包目录（建议副本），文件数几千以上、总体积几百 MB 以上。
2. 准备两个版本的更新包（`.eapack`）：相邻两个版本即可。
3. 打开「更多 → 首选项」，确认这几个值：`apply_space_check=1`、
   `apply_deep_verify=1`、`apply_clean_cache=1`。

## 清单

| # | 操作 | 预期 |
|---|---|---|
| 1 | 定位整合包 → 拖入更新包 → 开始更新 → 比对 → 确认更新 | 下载进度正常；**下载完成、提示"开始应用更新"的那一刻窗口不卡**（旧版会冻结好几秒） |
| 2 | 应用过程中看任务管理器 | 磁盘不会长时间 100%（同盘整合包应该几乎不产生磁盘 IO，只有日志里一句"瞬时搬运 N 个文件，实际复制 0.0B"） |
| 3 | 应用完成后 | 日志显示"更新完成 ✓"，按钮回到「开始更新」，右侧显示"本次更新已全部应用 ✓"，变更列表清空 |
| 4 | 再点一次「开始更新」 | 重新比对后应显示**无差异/已最新**（不会拿旧计划再搬一遍） |
| 5 | 把整合包放在 D 盘、数据库留在 C 盘，重做第 1 步 | 跨盘时会在日志里看到真的复制了字节；速度取决于 D 盘，界面依然不卡 |
| 6 | 更新过程中用任务管理器**强杀** Easier（在"正在应用更新"时） | 重新启动后弹出"上次更新没有正常结束"；整合包里**不应出现半截文件**（可以随便打开几个已更新的 jar 确认大小合理）；点「开始更新」重跑后收敛，残留的 `.xxx.pulses_tmp` / `.yyy.pulses_new` 被自动清掉 |
| 7 | 打开 Minecraft 后再点「确认更新」 | 报错信息人话化，例如"文件被占用或没有权限（请先关闭游戏/启动器/杀毒软件后重试；检测到 javaw 正在运行）"，**不是** `[WinError 5]` |
| 8 | 把整合包所在盘的空间占满到只剩几十 MB，再点「确认更新」 | 直接拒绝并说明"目标磁盘可用空间不足：需要约 X，当前可用 Y"，**一个文件都不该被改** |
| 9 | 更新一个带深层目录（路径 >260 字符）的整合包 | 不报 `找不到路径`；长路径文件能正常写入 |
| 10 | 更新完成后看「更多 → 缓存」 | 本次下载缓存已释放（日志有"已释放本次下载缓存 X"） |

## 出问题时请附上

* 日志面板全文（「更多 → 打开日志目录」或界面上的复制按钮）
* `<数据库目录>/cache/checkpoints/` 下的 json（如果有）
* 出问题的目录结构（`dir /s /b` 的前 100 行即可）
