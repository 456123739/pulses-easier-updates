## 三、真实网络实战（Modrinth 10 + CurseForge 10，69.0 MB）

用项目自己的 `differ` 分类 + `player_view._collect_download_tasks_from_diff`
生成任务，逐文件 SHA1 校验。

### 第 1 次运行（`tests/logs/v0.5.0-realworld.log`）

| 臂 | 说明 | 耗时 | 吞吐 | 校验 |
|---|---|---|---|---|
| A | 裸 urllib 顺序单线程 | 190.31s | 0.36 MB/s | 20/20 |
| B | 原版 downloader（`tests/_baseline`） | 92.67s | 0.74 MB/s | 20/20 |
| C | **RideX（锐驰引擎）** | **87.80s** | **0.79 MB/s** | 20/20 |

`C/A = 2.17×`，`C/B = 1.06×`。

> **本次运行网络明显偏慢**：A 臂 0.36 MB/s（v0.3.0 那轮是 1.4 MB/s），
> 说明瓶颈在 CDN 侧而不在客户端；三臂都接近链路上限时 C/B 自然收敛。
> 因此另跑了下面的轮转 + 归一化回合。

### 第 2 次运行（轮转 + 基准归一化，`tests/logs/v0.5.0-realworld-rotate.log`）

命令：`python3 tests/realworld_test.py --only-rotate --rotate-rounds 3 --calibrate`
（最小的 6 个文件，共 2.1 MB；每轮轮换 A/B/C 顺序，每臂开跑前先测一次
单连接基准用于归一化）

| 臂 | 各轮耗时 | 中位 | 归一化中位 | 校验 |
|---|---|---|---|---|
| A 裸 urllib 顺序 | 8.32 / 9.24 / 9.21 s | 9.21s | 12.85× 基准 | 6/6 · 6/6 · 6/6 |
| B 原版 downloader | 23.02 / 23.62 / 22.85 s | 23.02s | 32.34× 基准 | 6/6 · 6/6 · 6/6 |
| C **RideX 锐驰引擎** | **1.97 / 2.07 / 2.46 s** | **2.07s** | **3.15× 基准** | 6/6 · 6/6 · 6/6 |

**中位对比：C/A = 4.44×，C/B = 11.11×**，且三轮顺序轮换后 C 始终最快
（网络基准本身在 0.63~1.74 s/256KB 之间波动，归一化后结论稳定）。

> 说明：真实公网 CDN 的带宽波动可达数倍，单轮 A/B 比较**不可靠**。
> 因此项目里保留了"轮转顺序 + 每臂开跑前测一次单连接基准做归一化"的
> 配对回合（`--only-rotate --rotate-rounds 3 --calibrate`）。

## 五、修复前后行为对照（人工可复现）

两条 P0 的最小复现（现在都已被回归用例覆盖）：

**P0-1 目录误删**

```
instance/config/shipped.toml      ← 包里有、内容完全相同（仅 mtime 不同）
instance/config/user-only.toml    ← 玩家本地独有
overrides/config/shipped.toml     ← 更新包只带这一个

修复前：diff 判定 config 为文件夹级 MODIFIED → 默认策略「完全匹配」
        → rmtree(config) + copytree → user-only.toml 永久丢失
修复后：默认策略「替换重名」→ 合并覆盖；shipped.toml 更新、user-only.toml 保留
        （若用户显式选择「完全匹配」→ 整目录替换仍然成功，
          但失败时会自动 rename 回滚，不再出现"半删"状态）
```

**P0-2 元数据误写**

```
导出（源包无 overrides）→ 包内条目：
    ['modrinth.index.json', 'ea_settings.json', 'ea_hashes.json', 'ea_manifest.json']
修复前：玩家端把解压根目录当内容根 → 上面 4 个文件被写进整合包根目录
修复后：导出时无条件写入 overrides/ 目录条目；老格式回退分支再排除保留名
```
