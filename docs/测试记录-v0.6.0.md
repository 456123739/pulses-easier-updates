## 四、真实 GUI 测试（本机已具备条件）

之前所有 UI 测试都跑在 `tests/stubs.py` 的假 tkinter 上：能验证逻辑，
**证明不了**真实 customtkinter / tkinterdnd2 的调用是对的。
现在本机补齐了完整运行环境，可以跑真实窗口：

```bash
# 说明：本机没有 tkinter（系统包需要 root），也没有 DISPLAY，
# 所以用"解包 .deb + Xvfb"的方式把环境凑齐（全部落在 /tmp，不动系统）
#   tkinter / Tcl-Tk / BLT / Xvfb ← apt-get download + dpkg-deb -x
#   GUI 依赖 ← pip install --target /tmp/pylibs
export DISPLAY=:99
export PYTHONPATH=/tmp/pylibs:/tmp/tkroot/usr/lib/python3.11:/tmp/tkroot/usr/lib/python3.11/lib-dynload
export LD_LIBRARY_PATH=/tmp/tkroot/usr/lib:/tmp/tkroot/usr/lib/x86_64-linux-gnu
export TCL_LIBRARY=/tmp/tkroot/usr/share/tcltk/tcl8.6
export TK_LIBRARY=/tmp/tkroot/usr/share/tcltk/tk8.6

python3 tests/gui_smoke.py        # 真实窗口端到端（21 项）
python3 -m unittest discover -s tests -p "test_*.py"   # 264 项
python3 tests/e2e_flow.py         # 41 项（真实 CDN 下载）
python3 tests/e2e_incomplete.py   # 41 项
```

`tests/gui_smoke.py` 在真实库 + 真实窗口里跑完整链路：
创建主窗口 → 定位整合包 → 拖入更新包 → 比对 → 应用 → 校验结果与界面状态
→ 真正打开「更新受阻」子窗口（CTkToplevel）→ 截图。
没有 DISPLAY 或缺少 tkinter 时自动打印"跳过"并退出 0。

实测结果（2026-10-06，Xvfb 1400x1000）：

| 项目 | 结果 |
|---|---|
| gui_smoke（真实窗口） | **21/21 通过**，截图 1400×1000、977 种颜色（确认真实渲染） |
| 单元套件（真实 GUI 库在场） | 264/264 |
| e2e_flow / e2e_incomplete | 41 / 41 |

顺带发现并修正的两点：

1. `self.after(...)` 从工作线程调用，只有在**主线程跑着 mainloop** 时可用
   （否则 Tcl 抛 `main thread is not in main loop`）。这只影响测试写法：
   真实运行有 mainloop，测试必须改用 `mainloop()` + `after` 驱动，
   而不是 `update()` 轮询。
2. 真实 `customtkinter` 下 `PendingWindow`（CTkToplevel）的
   `transient()` / `bind(add="+")` 调用行为正确，类型注记只是为了安静
   Pylance。

## 三、关键行为验证（不是断言，是实际跑出来的）

1. **不再有整包副本**：`e2e_flow` 检查工作目录里不存在任何 `_merged`。
2. **移动而不是复制**：`e2e_flow` 检查 `overrides` 源文件在应用后已消失
   （被移走），而下载缓存按策略保留/释放。
3. **原子写**：`test_transfer` 里真的 `SIGKILL` 掉一个正在搬运的子进程，
   然后检查整合包里每个文件"要么是完整旧文件、要么是完整新文件"，
   并且只留下可以自动清理的 `.xxx.pulses_new`。
4. **中断自检**：`test_recover` 造出"旧目录改名后进程死了"的现场，
   验证副本被改回原位、半个新目录被丢弃。
5. **空间预检**：模拟"磁盘只剩一点"，验证 `InsufficientSpace` 直接拒绝、
   目标目录一个字节都没写、源文件也没被动过。
6. **检查点不再 O(n²)**：2 万个 `done()` 调用断言写盘次数 ≤20、
   单次写出 ≤16KB、累计 <300KB（旧实现是数百 MB）。
7. **内容级校验**：构造"大小一样、内容不对"的文件，
   验证只有开启内容级校验才会发现。
8. **整目录删除**：断言 200 个文件的目录只调用一次 `rmtree`。
