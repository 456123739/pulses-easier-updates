# 分支与同步流程

## 分支结构

### 主仓库 `pulses-easier-updates`

| 分支 | 用途 | 规则 |
|------|------|------|
| `main` | **稳定发布线** | 只接受功能修复和版本发布；**不接受美化改动** |
| `ui-glass` | **美化集成线** | 美化版代码的落地分支；可从 `main` 合入功能；美化改动经人工确认后可 merge 回 `main` |

### 美化版仓库 `pulses-easier-glass`

| 分支 | 用途 |
|------|------|
| `main` | 美化版主线（独立仓库、独立历史），是美化代码的**唯一权威源** |

## 同步方向

### 1. 功能修复：`main` → `ui-glass`（以及 → glass 仓库）

当 `main` 上有功能修复（如 db 迁移、更新后清包等）需要同步到美化版：

```bash
# 主仓库：把 main 的修复合进 ui-glass
cd /home/admin/NS/pulses_easier
git checkout ui-glass
git merge main
# 解决冲突（如果有），确认测试通过
git checkout main   # 回到稳定线
```

同步到 glass 仓库（单独的文件夹）时，手动 cherry-pick 或复制对应文件：

```bash
cd /home/admin/NS/pulses_easier_glass
# 从主仓库 main 拿对应 commit
git -C /home/admin/NS/pulses_easier log --oneline main
# 如果是单个 commit，cherry-pick：
git cherry-pick <commit-hash>   # 路径不同时需手动适配
```

### 2. 美化合并：`ui-glass` → `main`（需人工确认）

当 YG 确认美化版可以合并进稳定线时：

```bash
cd /home/admin/NS/pulses_easier
git checkout main
git merge ui-glass
# 解决冲突，全量测试，打 tag 发布
```

### 3. glass 仓库 → `ui-glass` 分支（镜像同步）

把 glass 仓库的最新美化代码同步到主仓库的 `ui-glass` 分支：

```bash
cd /home/admin/NS/pulses_easier
git checkout ui-glass
bash scripts/sync-glass-to-branch.sh
git checkout main
```

## 关键约束

- **`main` 分支永远不接受美化改动**（glass.py / motion.py / polish.py / overlay.py 等）
- `ui-glass` 分支与 `main` 共享同一棵文件树，`git merge` 原生可用
- glass 仓库的 `release/` 和 `tests/logs/` 不纳入镜像（主仓库的发布产物和测试日志是 `main` 线专属）
- 启动页 `SplashScreen` 是唯一保留的 `CTkToplevel`（主窗口 withdraw 期间需要独立窗口），不算弹窗
